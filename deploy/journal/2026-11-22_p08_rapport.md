## 5. Architecture livrée

- `registre.py` : schéma JSON + bornes + capacités + délai, au même endroit (validation `jsonschema`,
  `additionalProperties: false`).
- `deplacement.py` : contrôleur proportionnel saturé, période 0,05 s (20 Hz), `code_safety()` qui
  traduit `/safety/state` en code de §6.1. Logique pure, horloge injectée.
- `skills.py` : `Stop`, `Wait`, `MoveRelative`, `Rotate`, `CaptureImage`, `NavigateTo`, `SaveMap`.
  Un skill ne crée aucun abonnement : il lit `Etats` et publie par le contexte.
- `serveur.py` : `ActionServer` sur `/clawbot/execute_skill`, `MultiThreadedExecutor(3)`,
  `ReentrantCallbackGroup` pour l'action et `MutuallyExclusiveCallbackGroup` pour
  `/safety/state`, `/clawbot/capabilities/state`, `/odom`, images.
- `clawbot_sim/fake_base.py` : `/cmd_vel_safe` → `/odom` (mecanum) + `/scan` statique à 3 m.
- `clawbot-skill-server.service` : durcie (`NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=full`,
  `ProtectHome=read-only`, `StateDirectory=clawbot`, `ReadWritePaths`, `RestrictSUIDSGID`).

## 6. Défauts rencontrés et corrigés

1. **`Node.create_generic_subscription`… non, ici : la préemption par `stop`.** `ServerGoalHandle`
   n'a pas de `cancel_goal_async` ; la préemption passe par un drapeau lu par la boucle
   (`ctx.annule()`), et rcl_action refuse la transition `EXECUTING → CANCELED` sans demande client.
   Le résultat porte donc `CANCELED` tandis que l'état DDS est `ABORTED` (documenté dans le code).
2. **Rapport d'échec anonyme** : `"skill": "inconnu"`, `"params": {}` sur les chemins de rejet — le
   nom du skill et les paramètres n'étaient pas transmis. Trouvé par le contrôle de déploiement,
   corrigé, test ajouté.
3. **Collision de nom de fichier de test** : `test_preconditions.py` existait déjà dans
   `clawbot_director/` → `import file mismatch` en mode intégration. Renommé
   `test_exec_preconditions.py` (règle du skill : basename unique préfixé par le paquet).
4. **Durcissement de l'unité** : deux échecs successifs au démarrage — `ReadWritePaths` sur un
   dossier absent (code 226/NAMESPACE) puis `~/.ros/log` non écrivable sous `ProtectHome=read-only`.
   Corrigés par `StateDirectory=clawbot` et `ROS_LOG_DIR=/var/lib/clawbot/ros-log`.
