## Contrôles attendus

```bash
systemctl is-active clawbot-health-monitor                      # active
ros2 topic hz /clawbot/health                                   # ~1 Hz
ros2 topic echo /clawbot/health --once                          # level=1 (WARN), stale_flows contient /camera/depth/image_raw
ros2 topic info /diagnostics -v | grep -c "clawbot_health:"     # 10 statuts (un par flux déclaré)
pidstat 2 10 -p $(systemctl show -p MainPID --value clawbot-health-monitor)   # %CPU < 5
```

Le robot a la profondeur Astra muette (S09) : sa présence dans `stale_flows` avec `level=WARN`
est le résultat **attendu**, il prouve que le moniteur voit la panne connue.

### Défaut trouvé avant tout démarrage en production

`/voltage` figurait à la fois dans le manifeste (abonnement brut) et dans les entrées typées
(`Float32` pour remplir `RobotHealth.voltage`) : DDS refuse deux abonnements de types différents
sur un même topic, et le nœud mourait dans son constructeur (`RCLError: invalid allocator`).
Corrigé : un seul abonnement typé pour `/voltage`, qui alimente aussi l'estimateur ; test de
non-régression `test_manifeste_reel_un_seul_abonnement_par_topic`.
