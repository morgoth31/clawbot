## Défauts trouvés par ces contrôles

1. **Types des abonnements.** Le moniteur s'abonnait en `String` sur tous les flux. `raw=True`
   n'exempte pas du type : DDS n'apparie que des types identiques, donc `/scan` (LaserScan),
   `/odom` (Odometry), `/imu` (Imu) et `/cmd_vel_safe` (Twist) ne recevaient rien et étaient
   signalés périmés à tort — `level=ERROR` sur un robot sain. Corrigé : champ `type` dans le
   manifeste, `create_subscription` avec le type réel, test
   `test_abonnement_avec_le_type_reel_du_flux`.
2. **Coût CPU.** REQ-HEALTH-005 (< 5 %) n'est pas tenue, voir le tableau ci-dessous.

## %CPU (REQ-HEALTH-005) — exigence **non tenue**

Mesure par `/proc/<pid>/stat` (`pidstat` absent du poste), après 12 s de chauffe, sur 60 s :

| Configuration | % d'un cœur |
|---|---|
| manifeste complet (9 flux actifs, dont 3 flux image) | **39,5 % puis 43,4 %** (deux mesures) |
| sans les 3 flux image (6 flux actifs) | **16,0 %** |
| un seul flux (`/voltage`) | 6,3 % (fenêtre de 30 s, moins fiable) |

Conclusion : le budget de 5 % est dépassé d'un facteur 8. Un abonné `raw=True` **recopie chaque
charge utile dans Python** ; les trois flux image (≈ 52 messages/s, 0,6 à 1,2 Mo chacun) coûtent à
eux seuls ~25 points. Même sans les images, 6 flux à ~70 messages/s coûtent ~16 points, donc le
plancher dépasse déjà le budget : ce n'est pas un réglage, c'est un choix de conception.

### Quatrième voie appliquée (2026-11-22, après arbitrage opérateur)

Le moniteur est réécrit en C++ (`clawbot_health`, `ament_cmake`) dans la **même unité** :
souscriptions génériques par chaîne de type (`create_generic_subscription`), aucun objet
Python par message, décision, `RobotHealth` et `/diagnostics` dans un seul processus.
`trace_check.py` apprend à compter les tests gtest (`// REQ-...` avant `TEST(...)`), dans ses
deux copies (dépôt et skill), identiques — sha256 `efe844669ae36e4f…`.

| Version | 9 flux (3 images) | 6 flux sans image |
|---|---|---|
| Python (avant) | 39,5 – 43,4 % | 15,78 % |
| **C++ (après)** | **14,32 – 15,68 %** | **2,56 %** |

**REQ-HEALTH-005 reste non tenue** : tout ce qui n'est pas image passe de 15,78 % à 2,56 %
(sous le budget), mais les trois flux image coûtent encore ~12 points, uniquement par recopie
de la charge utile. Cette pile (Humble, ces éditeurs) n'offre ni topic filtré par contenu ni
zéro-copie exploitable depuis un éditeur standard. Aucun troisième contournement appliqué,
conformément à la consigne.

#### Défauts trouvés pendant la réécriture

1. `create_generic_subscription` ne conserve pas l'abonnement : sans garder le `SharedPtr`,
   le nœud reste sourd (constaté : `hz=0`, `age=null`). Idem pour les abonnements typés —
   `create_subscription` non stocké ne reçoit rien. Tous sont désormais conservés.
2. Le nœud exigeait `flows_file` par paramètre : l'unité démarrait puis abandonnait
   (`std::runtime_error`, `core-dump`). Le manifeste installé est maintenant le défaut
   (`ament_index_cpp`), l'unité n'a plus de chemin absolu à porter.

### Décision d'arbitrage

- **Option (a) — surveiller les images autrement — insuffisante** : elle ne traite que les images,
  et le plancher Python mesuré sans elles est déjà de 15,78 %. Aucun proxy fidèle n'existe :
  `camera_info` donne 10,0 Hz quand l'image de profondeur en donne 13,2, et 13,3 Hz quand l'image
  du poignet en donne 9,4.
- **Option (b) — porter les abonnements en C++ — insuffisante telle quelle** : appliquée aux seules
  images, elle laisse les 15,78 % du Python ; appliquée à tout le nœud, elle sort les tests du
  champ de `trace_check.py`, qui ne compte que les tests pytest (`rglob("*.py")`, aucune notion de
  gtest) — les six exigences HEALTH perdraient leur couverture automatique exigée par P00.
- **Quatrième voie proposée à l'opérateur** (arrêt pour arbitrage) : étendre `trace_check.py` au
  gtest (ou passer les tests HEALTH en boîte noire sur le binaire), puis réécrire `health_monitor`
  en C++ dans la même unité — abonnements génériques sans copie Python, décision et `RobotHealth`
  dans un seul processus, ~2–3 % attendus. C'est la seule voie qui tienne 5 % sans second service
  ni changement de topologie, mais elle demande une modification du cadre P00 avant le code.

## Notes d'exploitation

- Pendant la mesure, le manifeste **installé** a été remplacé deux fois par une variante (sans
  images, puis un seul flux) pour isoler le coût, puis restauré depuis la source : vérifié

  `/proc/<pid>/stat`, ce qui donne la même grandeur (CPU consommé par unité de temps).
