## 6. Écarts entre la documentation et le code

1. **`get_task` avec `task_id`** : le code l'accepte et répond `UNKNOWN_TASK` si la tâche est
   inconnue, mais **aucun appelant ne l'utilise** — le corpus ne peut donc pas l'exercer. Le
   schéma l'autorise (le comportement existe), le rapport le signale.
2. **`cancel_task` reçoit `task_id: ""`** du pont MCP quand l'outil est appelé sans identifiant :
   le directeur le traite comme absent (`demande.get("task_id") or None`). Le schéma accepte la
   chaîne vide ; c'est un silence du code, pas une erreur de contrat.
3. **Aucune autre divergence** : les cinq `op` et leurs paramètres relevés dans le code
   correspondent exactement à ce que les trois appelants envoient.
4. **Interface conservée** : `/director/command` garde `DirectorCommand` (JSON opaque) ; les
   nouveaux types ne sont encore servis par personne, ce qui est l'objet de P07 à P10.

## 8. Écarts par rapport au prompt

1. **Export JSON de la table d'erreurs** : le prompt laissait le choix entre génération à la
   construction et fichier versionné. Choix retenu : **fichier versionné** (`errors.json`) plus
   test d'égalité — il est relisible en revue, un diff montre exactement ce qui change, et
   `colcon build` n'a pas besoin d'exécuter du code du paquet pour produire une ressource.
2. **Validation des types générés** : `importlib.import_module("clawbot_interfaces.action.ExecuteSkill")`
   échoue — les types sont des **attributs** du paquet `clawbot_interfaces.action`, pas des
   sous-modules. Le test importe donc le paquet puis `getattr`.
3. **Résolution des schémas** : le module `clawbot_common.validation` peut venir du dépôt ou de
   `install/` ; un chemin relatif fixe ne marchait que dans un cas sur deux (30 échecs en série
   complète, 0 en isolation). Il cherche maintenant `share/<paquet>/` par `ament_index`, puis dans
   le dépôt, puis à côté du module.
4. **Déploiement fait** (étape 6 du prompt, optionnelle) : redémarrage du directeur en `warn`,
   contrôles consignés dans `deploy/journal/2026-11-22_p06_interfaces.md`. Aucun passage en
   `enforce`.
