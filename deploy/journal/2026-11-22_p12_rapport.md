## 3. Écart au prompt : TensorRT

Le prompt demande d'exporter le modèle en moteur TensorRT. Constat : **`tensorrt` est absent du venv
`/home/jetson/yolov5_env`** (`include-system-site-packages = false`), alors que le python système
porte `tensorrt 10.7.0` mais un `torch` **CPU**. L'export demande soit `pip install tensorrt` dans le
venv, soit un venv reconstruit avec `--system-site-packages` — **installation = porte opérateur, non
faite**. L'inférence actuelle tourne sur GPU via torch CUDA, ce qui satisfait déjà REQ-PERC-011
(99 % de `GR3D_FREQ`), mais la conversion FP16/FP32 demandée au §6.2 n'a pas été mesurée.

**Diagnostic en cours** : lancé à la main dans le venv, le nœud **démarre correctement**
(`YOLOv5s summary: 213 layers, … / yolo_node pret : backend=torch max_rate_hz=5.0`) et tient 90 s.
Sous systemd, aucune trace Python dans le journal, mais aucun éditeur n'apparaît : l'écart entre les
deux exécutions n'est pas encore expliqué (`TORCH_HOME` et `MPLCONFIGDIR` viennent d'être ajoutés à
l'unité, sans effet). Prochaine étape : lire `journalctl -u clawbot-yolo` en entier et comparer
l'environnement effectif du service (`systemctl show -p Environment`) à celui de l'exécution manuelle.

**Cause de l'échec d'export, précisément** : incompatibilité d'API entre le dépôt vendor
`/home/jetson/software/yolov5-7.0` et le TensorRT 10.7 de JetPack. Deux voies, aucune entamée :
patcher `export.py`/`models/common.py` du vendor (`max_workspace_size` →
`set_memory_pool_limit`), ou exporter avec `ultralytics 8.3.65` (présent dans le python système)
qui supporte TRT 10. Tant que le moteur n'existe pas, l'inférence reste sur torch CUDA — donc sur
GPU (REQ-PERC-011 tenue par la mesure : `GR3D_FREQ` 99 %), mais sans le moteur FP16 du §6.2.

**Seuil `wrist_vision` corrigé** : `ready_when` passe de 8,0 à **6,0 Hz** (mesure 6,9 Hz − 10 %),
avec le motif inscrit dans le manifeste. Écart au référentiel consigné : la caméra du poignet ne
tient pas les 8 Hz sur USB 2.0.
